## RPC endpoint switch

NEAR deprecated `https://rpc.testnet.near.org`; it now answers HTTP 429 "THIS ENDPOINT IS DEPRECATED". The owner's
refund run already used `--rpc-url https://test.rpc.fastnear.com`. M44 makes that the default everywhere a default
or a judge-facing command exists, and keeps every explicit `--rpc-url` / `DOCKSIDE_NEAR_RPC_URL` working:

| Where | Change |
|---|---|
| `scripts/testnet-deploy/lib/near-tools.mjs` `TESTNET_RPC_DEFAULT` (run-all and every `tool.mjs` subcommand) | `https://test.rpc.fastnear.com` |
| `scripts/testnet-deploy/run-all` usage text | default `https://test.rpc.fastnear.com` |
| `run-all --resume <run dir> --rpc-url <url>` (new `tool.mjs resume-rpc-url`) | new: replaces only the recorded RPC endpoint; checked by the same network rules against the run's recorded network (mainnet hosts and plain http refused); run-all prints the override and the recorded URL; `run-params.json` keeps the recorded one. `--network`, `--wasm`, `--journey`, `--amount-yocto`, `--relayer-key-file` and the other run settings are still refused on a resumed run |
| `packages/near/src/rpc.ts` `NEAR_TESTNET_RPC_DEFAULT` | `https://test.rpc.fastnear.com` |
| `scripts/testnet-deploy/verify-deploy.mjs` usage | `DOCKSIDE_NEAR_RPC_URL=https://test.rpc.fastnear.com` |
| M43 testnet runtime: `docs/runbooks/testnet-product.md`, `docs/USER-NEXT-STEPS.md` (§4, §5) | `DOCKSIDE_NEAR_RPC_URL` set to `https://test.rpc.fastnear.com` |
| README curl and PowerShell verification commands; `scripts/testnet-deploy/README.md` | `https://test.rpc.fastnear.com`; the README for run-all notes the deprecation and the resume override |
| Tests | `m16-run-all-tool`, `m24-run-all-windows`, `m02-rpc-client`, `m43-relayer-signer`, `m43-relay-and-startup` updated to the new default; new `packages/near/test/m44-run-all-rpc-override.test.ts` (4 tests: the default in both libraries and in run-all; `tool.mjs resume-rpc-url` keeps the recorded URL without an override and returns the override when given; the override is refused for a mainnet host, plain http, a public host on a sandbox run and an empty value; run-all's wiring still refuses every other setting on resume). The run-all wiring was also exercised by hand with `sh` (override printed and used; mainnet override `NETWORK_REFUSED`; `--wasm` on resume refused; each stopped before any RPC call) |

Historical status and evidence files (M05, M07, M24, M34 and their `docs/evidence/` records) keep
`rpc.testnet.near.org`: that is the endpoint those runs used. `docs/spec/` is unchanged. near-cli-rs signs and sends
through its own `testnet` connection; if that still names `rpc.testnet.near.org`, change it with
`near config edit-connection testnet` (noted in `scripts/testnet-deploy/README.md`). Journey logic is unchanged, so
the sandbox run-all suite was not re-run.

## Claim level

`WORKING_TESTNET` needs the direct native testnet path **and every required authority/recovery check** for the exact
build (REAL-PRODUCT-GATE), and the gate disallows "one operator or generic service credential controlling buyer,
supplier, inspector, ManifestAttestor, deterministic-policy and risk/policy test keys presented as normal
acceptance". These journeys sign every Dockside payload with keys derived from one seed by one operator. So, for the
exact build `4ff233b` on testnet:

- **item 6 (holds): PARTIAL (testnet).** PASS, single operator: an on-chain HoldRecord SET by the deterministic policy
  (`POLICY_SETTER`, `doc-mismatch@1`), the contract's release gate reporting `HOLD_ACTIVE`, and a RESOLVE
  (`RELEASE_HOLD`) by the separate risk/policy principal, then PAID. Not run on testnet: a hold SET by risk/policy,
  a direct `execute_release` attempt while held, deterministic-policy / buyer / supplier / inspector / wrong or revoked
  resolver signatures rejected, wrong reason / revision / manifest / nonce, expiry to EXPIRED_UNRESOLVED, API/UI
  denial, AI output unable to mutate the hold, and enrolled independent principals;
- **item 9 (refunds/recovery): PARTIAL (testnet).** PASS, single operator: MUTUAL_CANCEL (buyer and supplier signed)
  and EXCESS_FUNDING_RETURN (the funder's own account) after the one-hour cooling period, each to the original funder
  from its exact source bucket (`AVAILABLE`, `QUARANTINED`), conservation true. Not run on testnet: TRADE_EXPIRY,
  INSPECTION_FAIL, PERMANENT_HOLD, key-loss and partial-funding reasons, dispute/appeal/revocation branches,
  UNKNOWN/REVIEW recovery, unexpected assets and concurrent refund/release;
- items 3, 4, 5, 7 (beyond the positive path), 8, 10, 11, 12 and 13 stay **NOT_RUN** on testnet as in M34 (the M43
  product runtime has not been run on testnet yet).

The claim stays **IMPLEMENTED_UNVERIFIED**.
