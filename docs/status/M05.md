## Real vs simulated vs blocked

- **Real**: SQLite persistence (WAL, synchronous=FULL) shared by separate OS processes; SIGKILL/TerminateProcess
  of worker processes blocked at named boundaries; production `JsonRpcNearClient`, `EscrowContract` and
  `NearTxClient` over HTTP; the compiled escrow wasm executing every contract call.
- **Simulated**: the chain (`packages/journal/test/sim-chain.ts` over the M02 host): no nearcore, gas, storage
  staking, borsh transactions or signature checks; blocks advance per transaction or by test control. Fault
  injection (lost responses, dropped requests, status outage, deferred callbacks, hidden or contradicting
  receipts) is a property of that simulated node.
- **BLOCKED**: real NEAR testnet submission, receipts and finality need a relayer account and key (not allowed in
  this build). Exact user steps once allowed:
  1. Create a testnet relayer account and a FunctionCall access key for the escrow contract (wallet, not this repo).
  2. Implement a `TxSigner` that serializes and signs NEAR borsh transactions with that key (for example with
     `near-api-js`), held in the worker's secret store only.
  3. Run the worker with `JsonRpcNearClient` pointed at `https://rpc.testnet.near.org` (allowlisted) and
     `txValidityBlocks: 86400`, after the M04 runbook (`scripts/testnet-deploy/README.md` sections 1-5, 7).
  4. Record the transaction hash, the `EXPERIMENTAL_tx_status` receipts and the journal view as evidence.
- **NOT_RUN**: T-030 against a real provider; any funded-corridor operation.
