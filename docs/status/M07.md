## Real vs simulated vs blocked

- **Real**: HTTP transport, origin and CSRF posture (no CORS, custom auth headers, exact Origin and
  Sec-Fetch-Site checks), PoP sessions and per-request proofs, strict schemas, SQLite persistence and
  triggers, the isolated attestor and policy signer processes, the compiled escrow wasm executing every
  relayed call, the production `JsonRpcNearClient`/`EscrowContract`/`NearTxClient` over HTTP.
- **Simulated**: the NEAR chain (M02 host behind the M05 JSON-RPC server: no nearcore, gas, staking or
  transaction signature checks). Relay calls returned by the API are executed by the test as the relayer.
- **BLOCKED** (needs user action; no accounts, keys or deployments may be created by this build):
  1. Create NEAR testnet accounts for buyer, treasury, supplier and a relayer; deploy the escrow per the
     M04 runbook (`scripts/testnet-deploy/README.md`).
  2. Provision a relayer `TxSigner` with real custody and start `services/worker` with it (the entry point
     exits 78 `RELAYER_SIGNER_NOT_PROVISIONED` until then).
  3. Start the API with `DOCKSIDE_ESCROW_CONTRACT_ID=<escrow account>`,
     `DOCKSIDE_NEAR_RPC_URL=https://rpc.testnet.near.org`, `DOCKSIDE_ORIGIN=<web origin>` and
     `DOCKSIDE_OBJECT_STORE_DIR=<private directory>`; run the T-033 flow by hand with real wallets.
- **NOT_RUN**: T-034 DOM/storage/accessibility/screenshot boundaries (M08); INV-13 human acceptance with
  separate people on separate devices; any testnet or funded path.

## Honest limits

- Tests were written alongside the implementation, not strictly before it; the mutation check is the
  evidence that they detect defects in the authority, idempotency, export and redaction code. Writing the
  matrix found one ordering defect (exit and operator routes read intent/operation state before checking
  that the caller was the bound party), fixed in `fix(m07)`.
- The audit export is checksummed, not signed: it proves integrity against accidental or downstream
  change once the checksum is held, not origin. A signed export needs a dedicated export key (M09).
- Read routes call `ReleaseService.readiness`, which syncs contract state into the release journal; a slow
  RPC makes projections slow, never wrong.
- No rate limiting yet (SECURITY.md lists it; M09).

### Integrated API (M07)
With DOCKSIDE_ESCROW_CONTRACT_ID and DOCKSIDE_NEAR_RPC_URL set, `pnpm run api` also serves the trade,

`GET /v1/trades/:id/audit-export` returns a checksummed export; verify it with `verifyAuditExport`
