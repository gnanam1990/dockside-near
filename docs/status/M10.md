## Real vs simulated vs blocked

- **Real**: browser WebCrypto keys and PoP sessions in four separate contexts, every API route and authority
  check, SQLite persistence and append-only triggers, Ed25519 signatures, the compiled escrow wasm executing every
  call, the M05 worker and reconciler, the API's and the contract's delay checks (the one-minute delay is waited
  out on the wall clock).
- **Simulated**: the NEAR chain, the relayer, the funder wallets (`/control/fund`, `/control/funder-call`) and,
  in one refund test, the chain's block time (`/control/chain-time`, +61 minutes).
- **BLOCKED**: NEAR testnet accounts, deployment and relayer custody; a wallet connector in the browser (funder
  returns show the exact call instead); asset-recovery records (not served).
- **NOT_RUN**: testnet; INV-13 acceptance by separate people; browser races of release vs refund; `TRADE_EXPIRY`,
  `INSPECTION_FAIL` and `PERMANENT_HOLD` end to end above the contract; manual accessibility review.

## README additions (for a later consolidation stage)

```
### Destination change and refunds (M10)
The Agreement tab carries the dual-consent destination change; the Refund tab carries refund requests over
dockside-refund-v1 (API routes in services/api/src/refunds.ts). DOCKSIDE_DESTINATION_CHANGE_DELAY_MS (default
86400000, minimum 60000) sets the delay new proposals bind. Funder returns are submitted by the funder's own
wallet; this build has no wallet connector. Browser tests: apps/web/e2e/destination.spec.ts and refund.spec.ts.
```
