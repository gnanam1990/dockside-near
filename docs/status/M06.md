## Why it is blocked and what the user must do

A dry probe and anything beyond it need things this build may not create or hold:

1. Choose and pin the official 1Click client package and version (review its licence and API schema).
2. Register as a 1Click partner and obtain an API credential; store it in a secret manager, never in the
   repository or in `DOCKSIDE_*` plain variables.
3. Implement a `OneClickAdapter` that calls the **dry** quote endpoint with the trade's future bound
   recipient and maps the decoded response into `DryProbeObservation`; run T-024 and T-048 against it with
   redacted evidence.
4. Funded authorization (T-026, T-027, T-055) additionally needs a contract entry point that consumes a
   FundedPayoutAuthorization atomically once before the transfer to the deposit address, a verified
   corridor, and explicit authorization to move funds. Until then `DOCKSIDE_FUNDED_PAYOUTS` stays
   `BLOCKED` (the only accepted value).
