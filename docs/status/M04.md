## Simulated vs blocked

- Compiled-contract tests run under the M02 simulated NEAR host (`packages/near/test/sim`), not nearcore: no gas,
  storage staking or cross-block receipt scheduling.
- **Real testnet direct release (the positive path the prompt names): BLOCKED** — no testnet accounts, keys or
  signing are allowed in this build. Exact user steps: `scripts/testnet-deploy/README.md` sections 1-5 (deploy,
  init, register, fund) and the new section 7 (intent, approval, execute, read back). T-007's release half and
  the T-019 testnet positive path stay **NOT_RUN** until those transaction hashes exist.
- `PROCESSING`, `UNKNOWN`, `REVIEW`, `RECONCILING`, `ADJUDICATION` are reached in host tests by assigning the state
  after a real `execute_release`, because the reconciler that produces them is M05. `SUBMITTING` is real.
- INV-13 human acceptance with separate people on separate devices: **NOT_RUN** (tests use separately enrolled
  principals with their own keys and sessions, operated by one test process).
- No HTTP endpoints for release, exits or destination change (M07). No UI (M08).
- Funded payout profile: `FUNDED_RAIL_BLOCKED`; `FUNDED_AUTHORIZATION_EXPIRED` is `NOT_ELIGIBLE`.

## Handoff for M05+

- M05 owns `SUBMITTING -> PROCESSING | UNKNOWN | FAILED` and the later reconciliation states; the contract has no
  entry point for them yet. Keep: no refund row, exit, activation, new intent or second submit while unresolved;
  `REVIEW`/`ADJUDICATION` never accept a terminal outcome directly; a late receipt binds the original intent.
- `ReleaseService.sync` is the observation path; extend it rather than writing journal states directly.
- M07 should expose prepare/record pairs as typed endpoints; `prepareExecution` and `prepareActivation` are
  permissionless relays. The web catalog's guessed trade states should use `RELEASE_INTENT_STATES`
  (`@dockside/near`).
- A wasm upgrade changes `TradeRecord`'s borsh layout (new fields); nothing is deployed yet, so no migration is needed.
