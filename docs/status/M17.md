## Real-node findings (nearcore sandbox)

The sandbox run found two defects of the production `JsonRpcNearClient` that the simulated chain could not:

1. a real `block` header carries `timestamp` (nanoseconds) as a JSON number above 2^53, which the strict parser
   rejected, so `latestBlock()` failed against any real node. M15 landed the same parser change on main in
   parallel; the merge keeps main's version and `packages/near/test/m17-rpc-real-node-shapes.test.ts` covers it;
2. `view_access_key` for a missing key is a `result` carrying an `error` string ("... does not exist while
   viewing"), not a JSON-RPC error; it was reported as a malformed permission. Fixed here (`NOT_FOUND`, cause
   `UNKNOWN_ACCESS_KEY`); the simulated chain now answers the same way.

Red runs for both are in `docs/evidence/M17/red-runs.txt` (sections C and D).

## Real vs simulated vs blocked

- **Real**: every route, authority check and audit append; SQLite persistence; Ed25519 NEP-413 signatures from a
  locally generated wallet key, verified server-side and in the browser (WebCrypto); the export key in an
  isolated signer child process; offline CLI verification of a bundle downloaded in Chromium; nearcore 2.13.4
  answering `view_access_key` and final blocks to the production RPC client and the real API.
- **Simulated**: the chain in the API and browser suites (M02 host behind JSON-RPC, with an access-key registry
  standing in for AddKey/DeleteKey); the wallet (a page-announced test connector driven by the test process).
- **Not built**: retention deletion job; HSM/KMS custody for the export key; a third-party wallet integration.
- **NOT_RUN / BLOCKED**: NEAR testnet (ownership of a testnet account, deployment, funding); separate people on
  separate devices; manual accessibility review; 1Click (no credential accepted).
