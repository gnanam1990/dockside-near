# M43 — Relayer signer custody and the testnet product runtime

Status: **implemented and validated on a local nearcore sandbox; not yet run on NEAR testnet** (that run is the
owner's, with the owner's keys: [runbook](../runbooks/testnet-product.md)). No testnet transaction was sent in this
module. The escrow contract and the deployment `gnanam1990-dock-escrow2.testnet` (code hash
`7GEti5E6NWcjq8kHj5Gweed5HwggY1cxPD7cfbB65h8N`) are unchanged. Decision record:
[ADR-0025](../adr/0025-relayer-signer-custody-and-testnet-runtime.md).

## Why

Before M43 the API, worker and web app had only run against the simulated chain: the worker exited 78
(`RELAYER_SIGNER_NOT_PROVISIONED`), the party relay existed only in the local stack, and nothing checked that a
configured escrow ran the reviewed code.

## What was built

| Piece | Where | What it does |
|---|---|---|
| NEAR transaction encoder | `packages/near/src/near-tx.ts` | borsh `Transaction`/`SignedTransaction`, Ed25519 over `sha256(tx)` with node:crypto; matches the near-api-js serialization vector byte for byte |
| `KeyFileTxSigner` | `packages/near/src/relayer-signer.ts` | production `TxSigner`: near-cli-rs key file (path only in config), owner-only permission checks (POSIX mode, Windows ACL via `icacls`), refuses symlinks, oversized files and files inside a git checkout, key held in a private `KeyObject` and never serialised, signs only zero-deposit calls to the escrow, and checks on chain that the key is a function-call key restricted to the escrow (full-access refused) |
| Chain preflight | `packages/near/src/preflight.ts` | API and worker refuse to start unless `status.chain_id` is `testnet` (a sandbox id only on loopback), the escrow's code hash equals the manifest's and `get_config` says `near-testnet`; mainnet refused by config, host, chain id and account suffix |
| Worker runtime | `services/worker/src/{runtime,main}.ts` | outbox worker, reconciler and asset engine with the real signer; exit 78 with a reason code on any refusal |
| Party relay | `services/worker/src/relay.ts` | `/relay/v1/*` on loopback: allowlisted signature-carrying escrow methods, no deposits, JSON only, web origin only, rate-limited |
| Shared nonce lease | `services/worker/src/submit.ts` | relay and services submit through the journal's `withRelayerKey` lease and durable nonce table (one function-call key, many submitters, no nonce races) |
| Attestor / policy services | `services/worker/src/services.ts`, `pnpm run service-key` | keys in isolated signer children; the CLI generates seed files and signs the enrolment PoP challenge after recomputing its digest |
| Web | Overview funding panel; Organization → Policies | the exact `fund` call and a near-cli-rs command for the buyer's own keychain; registering an organisation's first EvidencePolicy |
| Configuration | `packages/core/src/config.ts` | `DOCKSIDE_ESCROW_MANIFEST`, `DOCKSIDE_NEAR_CHAIN_ID`, `DOCKSIDE_RELAYER_ACCOUNT_ID`, `DOCKSIDE_RELAYER_KEY_FILE`, `DOCKSIDE_RELAY_PORT`, `DOCKSIDE_MANIFEST_ATTESTOR_KEY_FILE`, `DOCKSIDE_POLICY_SERVICE_KEY_FILE`, `DOCKSIDE_TX_VALIDITY_BLOCKS`, `DOCKSIDE_WORKER_INTERVAL_MS` |

## What is still the owner's

1. Run the product on testnet with your keys: [docs/runbooks/testnet-product.md](../runbooks/testnet-product.md)
   (PowerShell, three terminals; the relayer function-call key from M34; service and export keys from
   `pnpm run service-key` / `pnpm run export-key`).
2. Capture the transaction hashes as the runbook's §3 describes and add them to the README (snippet below).
3. Independent people on their own devices (INV-13, gate item 3) need the web app behind HTTPS; on loopback all
   sessions are on your machine.

Not covered: HSM/KMS custody (same `TxSigner` seam), the near-cli-rs OS credential store (keys there must be saved as
a legacy-keychain file), and the asset-recovery execution path on a real chain (its call attaches a deposit, which a
function-call key cannot; it stays in review).
