# M56 — USDC journeys on NEAR testnet (audited M50 build on escrow3)

- Status: **the NEP-141 USDC rail ran on NEAR testnet.** The repository owner deployed the audited M50 contract on a
  fresh account `gnanam1990-dock-escrow3.testnet` and ran three run-all journeys there with Circle's testnet USDC
  (`3e2210e1184b45b64c8a434c0a7e7b23cc04ea7eb7a6c3c32520d03d4afcb8af`, 6 decimals) on 2026-11-13 (Windows host):
  **paid**, **hold** and **refusal** (six rejected transactions, then PAID). All three print `ok: true` in their run
  record, and every transaction was re-verified read-only on chain here (see "Read-only re-verification"). A
  **refund** journey was still running when this file was written (it waits a one-hour cooling period on chain
  time); it is listed as **pending**, see "Refund journey".
- Every Dockside payload was signed by **one operator** (keys derived from one seed per journey), as in M44, so the
  product claim level stays **IMPLEMENTED_UNVERIFIED** (see "Claim level").
- **Mainnet: not deployed.** The same audited contract is mainnet-ready behind a cap fixed at initialisation
  (25 USDC per trade by default, ADR-0028); deployment is pending (owner).
- Branch: `feat/dockside-m60-final-readme`, base main `74cafa5` (M50 merge). **No transaction was sent from this
  branch.**
- Evidence: [`docs/evidence/M56/`](../evidence/M56/) (what was and was not copied:
  [`files-summary.txt`](../evidence/M56/files-summary.txt)).

## Claim level

The NEP-141 rail is beyond REAL-PRODUCT-GATE item 2, which names native testnet NEAR. These runs show the audited
M50 build on testnet: deployment with the on-chain code hash equal to the manifest's, USDC funding from the recorded
funder by `ft_transfer_call` bound to the terms digest, release of exactly the trade amount to the bound supplier by
`ft_transfer`, a deterministic-policy hold that blocked the release and was resolved by the risk/policy principal,
and six refused calls with their exact codes. **USDC rail: PASS on testnet (single operator).** Every key was
derived from one operator's seed (INV-13), so the gate items stay as in M44 (items 6 and 9 partial; 3, 4, 5, 7
beyond the positive path, 8 and 10–13 not run on testnet). Mainnet: **not deployed** (pending, owner). The product
claim stays **IMPLEMENTED_UNVERIFIED**.
