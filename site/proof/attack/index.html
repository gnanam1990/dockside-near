    How this works, and its limits

    • Real transactions. The console's relay signs each attempt with the demo account's function-call key. That key can only call the escrow, cannot attach a deposit and holds only a gas allowance; the demo account is not a party, signer or destination of the trade.
    • Read back by your browser. The relay returns only a transaction hash. This page asks a public NEAR RPC endpoint for that transaction and shows the contract's own error code from it, and re-reads the trade's ledger afterwards.
    • Rate limited. One attempt per visitor every 20 seconds and a fixed number per ten minutes over everyone. If the relay is down or busy, the page replays attempts that were already recorded: it reads those transactions from the chain the same way.
    • What the codes mean depends on time. The buyer's approval and the evidence attestation are signed for 24 hours. After that, a replayed approval is refused as EXPIRED and a release lists the expired evidence first; the hold stays among the blockers. Every attempt is still refused, and the page shows the code the contract actually returned.
    • Not shown. This is the testnet deployment, and the trade's own keys belong to one operator's test run, not to separate companies.
