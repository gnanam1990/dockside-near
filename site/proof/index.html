Proof, read live from NEAR

Your browser asks a public NEAR RPC endpoint for the deployed escrow contract, its config, each trade's ledger and every journey transaction, and compares the answers with the values this repository expects. Nothing on this page is stored or computed in advance, and the page cannot send a transaction.

Try to steal this payment five attacks on a real escrowed trade, each a real transaction from an account with no authority, and the contract's refusal read back from NEAR.

What is checked, and what is not

  • Code. The code hash of the escrow account equals the hash in the build manifest, the manifest's SHA-256 is the same digest, and the contract bytes downloaded from the chain hash to it.
  • Ledger conservation. For every trade the page recomputes the invariant from get_ledger: each funder's buckets sum to what that funder funded, the deposits sum to the funded total, and committed value stays within the trade amount. The contract's own flag is shown beside it.
  • Payouts. The transfers the escrow account emitted in the journey transactions equal the release and refund intents the contract recorded as paid, to the same accounts.
  • Transactions. Every journey transaction exists, is final, succeeded, and called the stated method from the stated signer.
  • Not checked here. The chain shows which account signed, not which person held the key, and it does not show the off-chain documents. Rebuilding the wasm from source is a separate, longer step (pnpm run contract:reproduce).

Check it yourself

pnpm judge in a checkout runs the install, the unit tests, the contract tests and these same on-chain checks, and prints one PASS or FAIL table with the expected values. The expected values live in site/proof/proof-manifest.json, generated from the run records under docs/evidence/.
